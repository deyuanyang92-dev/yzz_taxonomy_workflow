# 文献定期归档 (literature intake) 设计

日期: 2026-10-15　状态: 待用户审阅　模块: `modules/literature`

## 1. 目标

用户经常下载文献、不命名, PDF 散落各盘. 定期把其中的多毛类 (含星虫、螠) 分类文献
按薛目录结构和命名规则归档进 `/mnt/n/多毛类分类文献-薛整理-杨接力/`, 使 PDF 库尽量全,
并增量更新本地全文库 `/root/yzz-literature/polychaeta.db`.

原则: **稳健优先** —— 不覆盖、不移动、不删除; 归档前用户过目; 可一键回退.

## 2. 已确定的决定 (用户 2026-10-15)

| 项 | 决定 |
|---|---|
| 归档位置 | 直接放入薛目录 (原"薛目录只读"改为"只增不改") |
| 复制/移动 | 复制, 原文件留原处 |
| 运行方式 | B 半自动: 定时任务跑脚本部分 (0 token); 判断 + 归档由用户说"更新文献库"触发, sonnet 子代理执行 |
| 频率 | 默认每周日 03:00 (可改) |
| 命名 | `<作者>, <年份>-<题目>.pdf` (薛目录现有 1769/2817 篇即此格式) |
| 薛目录原有杂名文件 | 本次不改名; DB 存规范名, 将来另行确认批量改名 |
| 去重 | 按"同一篇文献"管理 (版本 + 缺页), 不只按文件 |

## 2a. 范围扩展 (用户 2026-10-20)

1. **全盘 PDF 目录 + 映射表**: 电脑所有 PDF (现扫描 12 个盘 41,974 个) 都编目, 尤其文献.
   原文件不改名、不移动; 映射表保留原始文件名, 对期刊/书籍文献给出规范名
   `<第一作者…>, <年份>-<题目>` (同第 4 节规则). 非文献 PDF (说明书、票据等) 只登记类型, 不起规范名.
2. **多毛类 (含星虫、螠) 分类文献** 再从目录中筛出, 复制归档进薛目录.
3. **重复**: 自行比对; 与库内某份"完整一致" (同一篇且页不缺、质量不差) → 跳过. 其余按第 5 节.

全盘映射表 (Excel + DB 表 `pdf_catalog`), 每个 PDF 一行:
原路径 | 原文件名 | sha1 | 大小 | 页数 | 类型 (期刊论文/书/学位论文/报告/非文献/未定) |
DOI | 作者列表 | 年份 | 题目 | 期刊 卷(期): 页 | 规范名 | 书目来源 (crossref / pdf 元数据 / sonnet / 人工) |
类群相关性 (多毛类分类 / 星虫 / 螠 / 其他) | 同一篇 work_id | 版本角色 | 归档路径 (若已归档)

书目获取按成本从低到高, 前一步拿到就不走后一步:
1. 同 sha1 已解析过 → 复用 (41,974 个文件中重复拷贝很多).
2. 前 2 页文字 (无文字层则 OCR 首页) 找 DOI → Crossref API 取权威书目 (免费, 不需账号).
3. PDF 自带元数据 (Title/Author) 且与首页文字吻合.
4. sonnet 子代理读首页文字片段 (≤ 2000 字符, 每个子代理一批 ~30 篇), 输出结构化字段 + 置信度.
5. 低置信 → 标"待人工", 映射表中留空规范名.

## 3. 架构与数据流

```
定时 (Windows 任务计划程序 → wsl → python3 yzz.py literature update)      脚本, 0 token
  ① scan      各盘增量扫描 PDF (size+mtime 未变跳过) → discovery/pdfs_<盘>.tsv
  ② discover  复用 03: sha1 快筛 + 形态术语打分 → include / review / exclude
  ③ queue     新 include + review 写入 intake 表, status = queued
  ④ report    qc/待处理_YYYY-MM-DD.md

用户说"更新文献库" → skill yzz-literature                                     sonnet
  ⑤ judge     sonnet 子代理 3–4 个并行, 读首 2 页 (文字层或 OCR):
              是否分类文献 / 类群; 作者列表、年份 (实际出版年 + 封面年)、题目、期刊卷期页码
              每篇完成即写 intake (可断点续跑)
  ⑥ match     脚本: 同一篇判定 + 逐页对照 + 完整性 (第 5 节)
  ⑦ review    Excel 清单给用户: 原路径 → 建议 <作者夹>/<文件名>, 判定理由, 版本关系
  ⑧ archive   用户确认后复制归档 (第 6 节)
  ⑨ ingest    复用 01 / 02 / 04 增量入库 + OCR + 质量修复 → 带日期备份 DB
```

子代理提示词须写明: 禁止再调用 Agent; 每完成一项即写入结果文件/DB.
主线程只抽查, 不重读子代理已读内容.

## 4. 命名规则

`<作者>, <年份>-<题目>.pdf`

| 情况 | 写法 |
|---|---|
| 1 位作者 | `Moore, 1907-Descriptions of new species of spioniform annelids.pdf` |
| 2 位作者 | `Imajima & Higuchi, 1975-….pdf` |
| ≥3 位作者 | `Alalykina et al., 2017-….pdf` |
| 同作者同年多篇 | `Day, 1962a-…`, `Day, 1962b-…` (与库内已有比对后分配) |
| 实际出版年 ≠ 封面年 | `Bellan & Picard, 1966 [1965]-….pdf` |
| 题目过长 | 约 100 字符处按词边界截断 |
| 非法字符 `: / \ ? * " < > \|` | 换 `-` 或删去; 连续空白压成一个 |
| 变音符 | 保留 (ö é ç …) |
| 中/日/俄文 | 作者姓用原文或拼音, 题目保留原语言 |

文件名由脚本按子代理给出的结构化字段拼接, 子代理不直接产文件名.

作者夹: 第一作者 `<姓> <名缩写>` (如 `Day JH`, `Hartmann-Schröder G`); 优先匹配已有 528 个作者夹
(去变音符、大小写不敏感比较), 无匹配则新建. 星虫 → `Sipuncula References/`, 螠 → `Echiura references/`.

## 5. 同一篇判定与版本管理

sha1 只识别逐字节相同的拷贝 (第一道快筛). 同一篇的不同扫描、缺页版靠以下步骤:

1. **候选配对**: 书目字段 (作者 + 年份 + 题目模糊匹配 / 期刊卷页) 与库内文献比对.
2. **内容确认**: 两份文件有 ≥1 页文字相似度 ≥ 0.8 → 判为同一篇. 书目一致但内容无一页相似 → 标"待人工".
3. **逐页对照**: 每页在另一版本中找对应页 (相似度 ≥ 0.8), 得 A 独有页 / B 独有页.
4. **完整性**: 由出处页码推应有页数 (pp. 295–298 → 4 页, 图版另计), 与实际比较.

| 情况 | 处理 |
|---|---|
| 新版 ⊇ 旧版且多页 | 归档为 `<原名>_版本2.pdf` (放原文件旁), DB 标首选 |
| 新版 ⊂ 旧版 (缺页) | 不归档, DB 记"缺页副本 @路径" |
| 互补 (各缺不同页) | 两份都保留, Excel 标"互补, 建议合并", 用户决定 |
| 页同、质量不同 | 新版文字层 quality 高 ≥ 0.1 才归档, 否则不归档 |
| 同书目、无相似页 | 待人工 |

DB 新增 (草案):
- `works`: 一篇文献一条 (work_id, 作者列表 JSON, 年份, 封面年, 题目, 期刊, 卷期页, 规范文件名, 首选 doc).
- `doc_work`: doc ↔ work (角色: preferred / alt / partial / complementary, 缺页列表).
- `intake`: 待处理文件 (路径, sha1, size, mtime, 打分, 子代理判定 JSON, 状态 queued/judged/approved/archived/excluded/manual, 时间).
  已 excluded 的文件按 sha1 记住, 下次不再判断.

## 6. 归档与回退

- 复制到目标目录临时名 `.<名>.part` → 校验 sha1 → 改正式名. 断电不留半个文件.
- 目标已存在同名 → 加 `_2`; 永不覆盖.
- 每次归档追加 `_杨接力_新增清单.tsv` (时间, 原路径, 新路径, sha1, work_id), 并生成 `undo_YYYYMMDD.sh`
  (只删除本次新增且 sha1 仍匹配的文件).
- 子代理不确定 (年份/作者无法确定, 非分类性存疑) → `manual`, 不自动归档.
- 排除: 非分类文献 (生态、毒理等仅提及多毛类)、非多毛类/星虫/螠、残缺无法打开、加密.

## 10. 首次全盘编目执行顺序

1. 增量重扫 12 个盘 (上次 2026-10-14) → sha1 去重 → 得唯一 PDF 集.
2. 脚本: 类型初判 + DOI/Crossref + PDF 元数据 → 先出第一版映射表 (覆盖有 DOI 的现代文献).
3. sonnet 分批补无 DOI 的文献 (老文献、扫描件为主), 每批写入 DB, 可断点续跑; 每批后主线程抽 10 条核对.
4. 多毛类分类子集 → 同一篇比对 → Excel 给用户过目 → 分批复制归档 (第 6 节).
预估: 唯一 PDF 约 1.5 万, 其中需 sonnet 的估计数千篇; 首批跑完报实际数量与耗时再继续.
